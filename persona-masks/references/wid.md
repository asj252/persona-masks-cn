# wid：把问答写成文件

wid 是 write it down。用户要求把某段问答留成项目里的一份文件时使用；它是问答产物，不是记忆，也不写进 LOG。

## 调用与范围
- 触发：`wid:` 前缀，模块写法 `$wid`（可与其他模块组合），或自然语言「wid」「记下来存成文件」。
- **默认范围**：本次前缀后的用户内容，与本次完整回答。
- 前缀后的文字可以是**对已有内容的指示**，例如「wid: 上述描述，用英文」：先按指示处理所指的内容（此例为把上一则回答译成英文），再写入。所指不明时先问指的是哪一段。
- **只对本则生效**：wid 不适用 SKILL.md「同一任务中未重写的模块沿用」；下一则不再写文件，除非用户指定向后延伸。
- **延伸**：只有用户明确指定时才纳入当前可见的先前问答，或持续追加指定的后续问答；到指定边界或用户明确关闭时停止。不自行扩大到整段对话，不声称读得到不可见的历史，也没有后台持续记录。

## 输出位置
1. 用户本次指定的路径优先（相对路径以项目根目录解析）。
2. 否则读项目层写明的默认目录（项目有 `personas/` 时，写在 `personas/README.md` 的「wid 默认目录」一行）。
3. 仍无唯一目录时先询问，等用户给出再写；不自行挑目录，不写进 `personas/` 的面具资料夹或个人资料目录。
用户明确要求「记为本项目默认」时，才把目录写进 `personas/README.md` 的那一行；项目没有 `personas/` 时不自动建立，先问用户记在哪里（或只用于本次）。不自动修改项目指令档（如 AGENTS.md、CLAUDE.md）。

## 格式
- 每次调用一份 UTF-8 Markdown，文件名用日期与简短主题，同名时加序号，不覆盖旧文件；向后延伸时追加到同一份。
- 开头写项目、保存时间与实际记录范围；正文依次是用户原文与完整回答（按指示处理过的，写处理后的结果，并注明所据原文的位置）。
- 回答里有已渲染的图时，图档与 Markdown 放在一起并以相对路径引用，也保留图的源码（如 Mermaid）。
- 写完重读核对，再在聊天中给出文件链接与一句说明；无法写入时如实说明未写。

## 边界
- 项目关于凭证、数据、模型产物与提交的规定仍然适用；指定路径本身不授予额外的文件权限。
- 在按任务书分工的项目里，wid 属于用户明确指示「当场做」的单次写入，不经任务书，并在回复中注明是例外；写入后照项目的提交规矩提交，或告诉用户尚未提交。戴 c 时也可以写 wid 文件，但只写这一份，不借此改动别的文件。
- wid 文件不替代任务书、决策记录、面具记忆或个人 PROFILE／LOG。
