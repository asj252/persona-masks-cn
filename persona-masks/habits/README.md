# 习惯包

习惯包是**某位用户在用的一组个人规则**，打包成可选安装项。每个包一个目录 `habits/<名称>/`，内有 `HABIT.md`：开头说明是谁的什么工作方式、适合谁、依赖什么宿主能力，接一张规则表（条目键｜适用范围｜有效规则｜出处）。
系统核心不依赖任何习惯包；不装的用户照包默认。装了的规则写进用户自己的 PROFILE 才生效，与包默认冲突时以 PROFILE 为准。

| 包 | 一句话 | 依赖 |
|---|---|---|
| [`module-tweaks`](module-tweaks/HABIT.md) | smd 的行数限制只管终端命令；kis 只对启用的那一则生效 | 无 |
| [`brief-workflow`](brief-workflow/HABIT.md) | a 写任务书、c 独立审查、e 默认由 a 以子 agent 派出实施（可另开 session）、c 查验、a 判定的完整工作循环（含无原稿时先写大纲、终审与回顾，以及用户限期授权的无人值守） | 宿主的子 agent 与独立 worktree（另开 session 时需要跨 session 消息、任务芯片）、session 改名等；资料目录为 git 仓库 |
| [`craft`](craft/HABIT.md) | 验收标准写得出检查脚本；统计推断先定分析单位；预先验算；起草前对照错误形状自查；另有五条（声明范围、替换句字数、替换表、未舍入的差值、c 的替换句预检） | 无 |

## 何时询问
只在有 agent 协助安装或升级、或用户要求时，列出上表并逐包询问是否安装；日常调用不主动询问。

## 安装
1. 确定资料目录（同 SKILL.md 开场规则）；不存在 PROFILE 时按 [资料与日志](../references/state-and-log.md) 建立。
2. 先在 LOG 准备一个事件（事件键按 LOG 规则取），范围写「安装习惯包 `habits/<名称>@0.5.2`」。
3. 把 `HABIT.md` 规则表逐行写进 PROFILE：条目键、适用范围、有效规则照抄；**来源栏**写「`habits/<名称>@0.5.2`＋本次安装的 LOG 事件键」；状态「已采用」。「出处」栏是作者原 LOG 事件键，只作出处，不写进用户的来源栏。
4. 包内另有安装前提或模板的（如 `brief-workflow`），按该包说明处理。
5. 重读 PROFILE 核对，再追加 LOG 事件，写明实际写入的条目；部分完成也如实记录。

## 同键条目
PROFILE 已有同键条目时（例如从 0.1.0 升级前已手工采用过）：
- **内容相同**：不重复写，只在来源栏补注 `habits/<名称>@0.5.2`。
- **内容不同**：逐条询问用户保留哪一份（或合并成哪一句）；未答复前保留原条目，不静默覆盖。
两种情况都记进本次安装的 LOG 事件。

## 升级与卸载
- **升级**：新版本的包按上文重新比对同键条目；用户已自行修改的条目按「内容不同」处理；已装包新增的条目逐条询问是否加入。都记进本次升级的 LOG 事件。
- **卸载**：从 PROFILE 移除来源栏标该包的条目，LOG 记一个事件并引用原安装事件键；来源栏同时有用户自己的事件键与 `habits/` 标记的条目（安装时内容相同而补注者），只去掉 `habits/` 标记，不删条目；与用户自己的条目合并过的，逐条询问。

## 边界
- 习惯包可以依赖宿主能力，须在包内写明，并写明宿主不支持时怎么办。
- 习惯包不能扩大宿主或项目既有的权限；需要额外权限的做法须由项目的任务书或用户明确授权才生效，习惯包本身不授予。
- 习惯包不能取消 c 的独立上下文、不能要求 c 接收作者的推理、不能给 c 否决权。
- 以后可以有别的习惯包；新包照本目录的结构，不改系统核心。
