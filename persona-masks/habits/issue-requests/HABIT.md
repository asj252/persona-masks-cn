# 习惯包 issue-requests：skill 的更新需求开成 issue

**是什么**：本包作者管理自己一组 skill 的做法：在任何项目里发现某个 skill（含 persona-masks 本身）该改的地方，就开在一个固定仓库的 issue 里，当作需求队列，不在各项目里另存改进 log；改动合并后在 issue 留言，再关闭。
**适合谁**：自己维护 skill 的人；还没有收需求的仓库的，建议先建一个私有仓库当需求中心（hub）。不想让需求离开本机的人不适合，照包默认记 LOG 即可。
**不含**：怎么从 issue 写任务书、审查与实施，见 [brief-workflow](../brief-workflow/HABIT.md)；本包只管需求的登记与收尾。
**与 LOG 的关系**：系统调整照旧记进资料目录的 `LOG.md`（见 [资料与日志](../../references/state-and-log.md)）；本包另加需求队列。同一件事两边都有时，LOG 事件写上 issue 编号。

## 依赖的宿主能力与不支持时怎么办

| 宿主能力 | 用在哪 | 宿主不支持时 |
|---|---|---|
| 能执行 GitHub CLI（`gh`）或同等的 issue 接口，且已登录 | 开 issue、留言、关闭 | 按 `issues.fallback` 处理 |
| 联网 | 同上 | 同上 |

- **权限**：开 issue、留言、关闭都是对外动作。本包不授予权限：默认先问用户；用户或项目明确授权的（例如项目规则写明需求仓库可直接开 issue 与留言）才可不问，关闭一律先问。与 SKILL.md「项目层与习惯包都不能扩大宿主或项目既有的权限」一致。

## 安装
按 [习惯包](../README.md) 的步骤把下表逐行写进 PROFILE。另外：
1. 先问用户收需求的仓库（如 `<owner>/<repo>`），以及开不了 issue 时的后备文件路径（可以不设）；把下表有效规则里的 `<需求仓库>`、`<后备文件>` 换成用户的答复（没设后备文件的，`<后备文件>` 写成「未设」），其余文字照抄。用户还没有需求仓库的，建议先建一个私有仓库专门收 skill 的需求（例如 `skill-requests`），建好再装；用户不建就不安装本包，照包默认记 LOG，并在 LOG 注明。
2. 仓库已有标签约定的，照它的约定；本包不建标签。

「出处」栏是作者资料目录的 LOG 事件键，只作出处。

| 条目键 | 适用范围 | 有效规则 | 出处 |
|---|---|---|---|
| `issues.where` | 所有项目里，发现任何 skill（含 persona-masks 本身）该改的地方时 | 开在 `<需求仓库>` 的 issue，标题写「[<skill>] <一句话>」，标签照该仓库的约定；不在各项目里另存 skill 改进 log。 | skill-requests-to-issues-20261015 |
| `issues.content` | 写 issue 时 | 一条 issue 只放一件能单独判定的事（同一个 skill 的几条小修可以合成一条，正文逐条编号）；写归属、问题、建议、出处（项目、实例、任务书、复盘文件）与用户是否已决定。只写看到的事；用户没说过要改的标「提议」，不标「已决定」。仓库公开时，不写私人路径、未公开项目的细节与个人资料。 | skill-requests-to-issues-20261015、issue-habit-hub-privacy-20261020 |
| `issues.consent` | 开 issue、在 issue 留言、关闭 issue 时 | 都是对外动作：默认先问用户一次（说明仓库、标题与要点）；用户或项目已明确授权的照授权直接做，在回复里报 issue 编号与链接。关闭一律先问用户。 | skill-requests-to-issues-20261015 |
| `issues.fallback` | 开不了 issue 时（宿主不能执行 `gh` 或同等接口、没联网、没登录） | 后备文件：`<后备文件>`。设了的，追加到它的末尾并标「未转 issue」；未设的，在回复里给出 issue 全文（标题、标签、正文）。两种都说明未开，不声称已开；能开时再转成 issue。 | skill-requests-to-issues-20261015 |
| `issues.close` | 需求经改动合并之后，或用户否决需求时 | 在 issue 留言写合并提交与任务书（或改动说明）的路径，经用户同意再关闭；只做完一部分的，没做的另开 issue，不让旧 issue 半开着。用户否决的需求，留言写明用户原话，经用户同意后关闭。 | skill-requests-to-issues-20261015 |
