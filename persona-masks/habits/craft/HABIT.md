# 习惯包 craft：十一条工作手艺

**是什么**：本包作者从项目层的错误形状中升为个人全局规则的四条手艺：验收标准要能机械判定（在同一项目的多份任务书中反复出现）；统计推断先定分析单位（在两个不同实例中各出现一次）；预先验算、起草前对照错误形状自查（都只在一个项目验证过，作者裁定仍升）；0.4.0 起又加两条，0.5.1 起再加三条，0.6.1 起再加两条（验证范围见各条的出处栏）。
**适合谁**：写或审任务书、验收标准的人（配合 `brief-workflow` 包更顺，但不依赖它）；做统计推断、检验或两组比较的人。
**依赖**：不依赖任何宿主能力；检查脚本用项目现有的语言与工具即可。
**安装**：按 [习惯包](../README.md) 的步骤把下表逐行写进 PROFILE。「出处」栏是作者资料目录的 LOG 事件键，只作出处。

| `craft.ac-scriptable` | 全局（所有项目），a 起草任务书、c 审查任务书时 | 每条验收标准都必须写得出检查脚本：改写成字符串、正则、计数或集合相等，不用「一致」「等」「只出现在定义句中」这类要人判断的措辞；判据的字面须与规格正文要求的写法逐字相符（引号、符号）。起草后拿**基准版本**跑一遍，确认改前会失败、照规格改后会通过；再手工造一两个反例（如把新句改回旧句、多加一个附件、在开头插一个空格），对应的条目必须判败；写「全文不含 X」一类全局条目时，先在基准稿上跑一遍，看有没有被它锁住的基准句；c 审查时对每条 AC 问「脚本怎么写」。 | 20260927-0840-promote-lessons |
| `craft.analysis-unit` | 全局（所有项目），凡涉及统计推断、检验或比较两组时（a 定判据、c 审查、e 量测） | 先问「一个独立的单位是什么」，按那个单位聚合后再做推断；彼此相关的观测（同一天的各小时、同一 seed 的多座位、同一人的多次量测）不当独立样本。两种单位的结果差几个数量级即是伪重复的信号；聚合后仍有相关时，结论要写明只是较合理的近似。 | 20260927-0840-promote-lessons |
| `craft.precheck` | 全局（所有项目），a 起草任务书、c 审查任务书时 | a 起草任务书时，凡规格依赖的数字、输出、字数或逐字的预期稿，都先实际跑一遍（预先验算脚本入库，如 `tasks/T{编号}/precheck_*.py`），在任务书中写明结果、对应的是哪个量、保留几位与基准提交；任务书修订后在最后一版的提交上重跑。预先验算时把示范的输出打印出来读一遍、把图渲染出来看一眼，不只核数字。c 审查时独立重算，不直接信任 a 的输出。打印保留足够的位数（中位数印 1 位小数，不用 `:.0f`）；规格依赖抽样时，逐个数据集写出抽样的次序与写法（先抽哪一类、直接抽还是经分解变换、新数据是否接着同一个生成器）。 | 20260928-1542-promote-lessons-2；20261006-1750-0.4-candidates |

| `craft.claim-scope` | 全局（所有项目），写收束句、小结、总结时 | 收束句、小结、总结里「在……上」「假设不对时」「一般」这类范围词，范围不得超出正文量过的那几份数据与设定；写之前把本文出现过的每一种同类设定逐一代入，不成立就只写量过的那几种。 | 20261006-1750-0.4-candidates（三个单元的终审各挡下一次） |

| `craft.replacement-table` | 全局（所有项目），a 起草修订类任务书、写替换句时 | 修订类任务的替换句一律写进一张替换表（如 `tasks/T{编号}/a_fixes.py`：编号、位置、现句、替换句、次数），build 与 check 脚本都 import 它，不另抄。验收必含：正向套用等于新稿、逆向还原等于基准；现句在该文件里恰出现 1 次；增补型（替换句以现句开头）由脚本判 `replacement.startswith(original)`，其验收写「现句只出现在替换句之内」，不写「不再出现」。检查脚本判越界的提交范围写成 `START..<合并本任务的提交>`，合并后固定为常量，不用 `START..HEAD`；合并之后的小改也走替换表、重建，不手改；要证明「一字节不动」时，字节基准取 e 开工前在自己 worktree 里存的工作区快照（路径、换行、SHA256），不取 `git show` 的字节（自动换行转换开着时，库内与工作区的换行可能不同）。 | 20261010-0941-0.5.1-scope（来自一个长期项目的多个修订任务，凭眼分类增补型出过三次错） |
| `craft.unrounded-diff` | 全局（所有项目），写含数字的任务书、正文、小结时 | 任务书与正文里的差值、平均、比值一律由脚本以未舍入的量算出再舍入，不拿两个已舍入的数相减；手算要代入的常数保留正文印出的位数，「统一舍入」只管读数、不管参与算式的量。 | 20261010-0941-0.5.1-scope（来自同一项目，同一形状出错五次） |
| `craft.c-sentence-precheck` | 全局（所有项目），c 写替换句、建议句，或 a 采纳 c 的替换句时 | c 给出的替换句与 a 的规格句受同一套检查：交出前用检查脚本的禁用清单、必含清单与计数函数跑一遍（含套回所在处的字数）；写「数值误差」「来自……本身」一类归因句时，要求把两部分分开印出；「统一舍入」前先检索被改的数参与的算式。 | 20261010-0941-0.5.1-scope（来自同一项目，终审建议多半起于持续 c 自己的替换句） |
