## 4. 记忆的规矩

- `MEMORY.md` 是索引：按实例分节，一行一条、指向条目档，不放内容。条目档一档一主题，写绝对日期，标实例。
- 只在一个实例验过的教训不升 `#all`，要在两个实例各自验过。
- **不重复已有文档**：{现况、待办、决定、任务、规范各在哪}。面具资料夹只放那些文档放不下的东西。
- 每个面具写自己的记忆，写在自己的资料夹，不替别的面具写（a 有特权，可以写别的面具的记忆）。当场写的有三类：用户说「记下」「记住」（写在哪里按「教训放哪」一节的判准；判为项目指令档的，先提出规则句，经用户同意再写）；用户纠正了本面具的做法（写被纠正的做法和纠正后的做法）；本面具的产出被判定（采纳、否决、成立、不成立）时，写判定的理由或错误形状（面具是已结束的子 agent 时，由 a 在判定时代写）。其余不当场写。

### 4.1 教训放哪

判准：**不管戴哪个面具，不知道这件事就会出事吗？** 会 → 项目指令档，缩成一两行规则句，经用户同意再写；不会 → 用得到它的面具资料夹。

| 这条教训是… | 放哪 |
|---|---|
| 硬规矩、与用户的约定 | {项目指令档} |
| 起草、定验收标准、裁决的手艺 | `architect/` |
| 反复抓到的错误形状 | `critic/shapes.md` |
| 实施、检查、回报的手艺 | `engineer/preflight.md` 与条目档 |
| 只对某一次工作成立的读数与结论 | 该工作的任务书或报告，不进任何指令档 |
